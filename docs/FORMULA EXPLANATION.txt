Fever Fill / Fever Time Formula Notes (Game-Parity)

This file is a plain-English companion to:
- `docs/FEVER_TIMELINE_MATH.md` (math spec)
- `docs/Implementation Records/FEVER_FIX_PLAN.md` (server-parity timeline details)

Fever fill is based on "song key hit count"

In the game source, the fill per hit is derived from the song's hit count (the number of key hits, not raw hit-objects). In our exported song data this is typically represented as:

song_key_hit_count = Total Notes - Long Notes

Conceptually (see the historical decompile in `OLD LEGACY SOURCE GAME CODE/.../Avatar/GearStats.lua`):

fill_per_perfect = 1 / (song_key_hit_count * fill_base_perfect)
fill_per_great   = 1 / (song_key_hit_count * fill_base_great)

Where:
- `fill_base_perfect` is derived from the Fever Fill Rate stat and is 0.333 at the base point on the stat curve.
- `fill_base_great = 2 * fill_base_perfect`, so Great fills exactly half as much as Perfect.

This is why "0.333" shows up: it is a key point on the Fever Fill Rate stat curve, not a magic constant.

Why we use ceil for notes-to-fill

We often work in "perfect-note units" where:

raw_fill = (song_key_hit_count * 0.333) * ff_factor(FF)

Then the all-perfect notes required to reach or exceed the threshold is:

notes_to_fill(0) = ceil(raw_fill)

Activation is on the note itself

The hit that crosses the threshold is scored as a Fever note (activation is "on the note itself"). So the number of non-fever scored notes before the first fever window is:

non_fever_notes(section 1) = notes_to_fill(0) - 1

The transition-note ("wasted note") effect

On the server processing path, the ordering is effectively:
1) apply fill/drain for the hit
2) update the powerbar by delta time
3) score the hit

This creates a transition note after each fever window:
- the note where fever expires is scored as non-fever,
- but it did not contribute fill (because fill was applied while still in fever).

As a result, the later non-fever sections use:

non_fever_notes(section 2+) = notes_to_fill(0)

This is the reason `FEVER_FIX_PLAN.md` and the solver use section-aware logic (section 1 uses -1, sections 2+ do not).

Fever time (duration)

The base fever duration scales with song length and a 15% constant:

fever_time_cas = (last_note_time * 0.15) + 0.15

Then the Fever Time stat applies a multiplier (see GearStats).
